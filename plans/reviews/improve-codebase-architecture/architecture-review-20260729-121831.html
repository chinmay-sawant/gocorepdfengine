Deepening candidates

1. Collapse dual assemblers

Strong in-process

engine/engine.go · engine/document.go

Before — two procedures (subset fixed, Tabs drifted)

Generate
font · ICC · UA wrap · structure · catalog
subset: yes · Tabs: yes
GenerateDocument
helpers extracted · product path
subset: yes
Tabs: missing

After — one deep assembly module

interface: assemble(DocumentConfig)
font embed
profile apply
structure attach
catalog build (+ Tabs)
Generate / GenerateDocument = thin adapters

Problem

Policy graph written twice; subset fixed, Tabs already drifted.

Solution

One assembler; both entry points call it. Reuse document helpers.

Wins

  • locality: assembly bugs concentrate
  • leverage: one path, two callers
  • closes C1/C8 class permanently

2. Compliance profile module

Strong

engine/*.go · pdfa/ · meta/ · color/

Problem

Mode bits + ifs; pdfa helpers unused; shotgun surgery.

Solution

Profile owns OutputIntent, MarkInfo, Lang, TrailerInfo, Tabs, Metadata flags.

Wins

  • locality of compliance rules
  • real pdfa leverage
  • one test surface for profiles

6. Shared render finish helper

Worth exploring

render/contract_note.go · render/template.go

Problem

Parallel PageContent mapping, UsedText, mode, footer.

Solution

render.finish(builders, meta, mode); domain files only build tables.

Wins

  • less product glue envy
  • consistent compliance flags

Top recommendation

Protect the 2× win, then unify assembly

Keep baselines/ gates green, then make Generate share the product assembly path so Tabs/subset/font cannot drift. Do not trade ~2.3–2.5k ops/sec for speculative abstraction.
